# Plan: AI as the entry point to FlameMap

Status: planned 2026-11-14. Supersedes the "live mode" part of `AI_PLAN.md` §2 for the submission; the key-based mode stays as a documented extension.

## Goal
The challenge asks for an "SI-powered dashboard". Today the AI text is a panel on the Rank page and the 4th nav item. This plan makes the AI the first thing a visitor (and a judge) sees, and tells the story of *how* the AI is used:

> All interpretive text in FlameMap (briefs, answers, related-study links, summaries) was **written by AI** (Claude Opus 5.5 via Claude Code) at build time, from the computed data only, then **checked sentence by sentence** by `pipeline/ai_build.mjs` and signed off by a person. We chose this so the site needs **no inference keys, no server and no per-visit cost**, and every answer can be checked before anyone sees it. The design is ready for a "bring your own key" mode for open-ended questions (see "Extension" below).

## 1. Mission briefing as the home page (`/`)
New `app/src/pages/Briefing.tsx`. Rank moves to `/rank`.
- Hero: "Ask NASA's fire experiments about your mission", a question box (the Ask search) and big environment cards + task toggle.
- Then: the AI brief (full width, citation chips) → "What has never been tested" (computed gaps) → top 3 studies, linking to "See the full ranking and math" → 4–6 suggested questions for the selected environment (from `qa.json` tags).
- Footer strip "How this AI is kept honest": counts from `ai_meta.json` (sentences checked, unsupported numbers = 0, reviewed by a person on date, generated by Claude Opus 5.5, no API key used at runtime).
- Old links: `#/?...` with `w` or `cmp` redirect to `/rank`, others stay on the briefing.

Nav: **AI**: Briefing · Ask the evidence · How the AI works | **Data**: Rank · Evidence map · Explorer · Compare · Sources.

## 2. Ask the evidence: semantic search over a larger checked set (Option C)
**More answers.** Grow `pipeline/ai/qa.json` from 16 to about 150 questions, written in a Claude Code session from `context.md` and checked by `ai_build.mjs` like the current ones. Coverage per environment × task, per investigation ("What did BASS-II find?"), per gap ("Has anything been tested at Mars gravity?"), plus Earth-applications questions. Add 2–3 paraphrases per question to improve matching.

**Semantic matching in the browser.**
- Build time: a new step in `ai_build.mjs` embeds every question and paraphrase with a small sentence-embedding model (transformers.js, `all-MiniLM-L6-v2` quantized, ~23 MB; version pinned at install) and writes `app/public/data/qa_vectors.json` (int8, ~100 KB).
- Runtime: the same model is self-hosted under `app/public/models/` (no third-party fetch) and loaded lazily on the first question. Only the visitor's question is embedded; cosine similarity against the stored vectors.
- Until the model has loaded (or if it fails), the current keyword matcher answers. The UI never blocks.
- Thresholds: strong match → show the answer; weak → "closest checked answers" list; none → say plainly that no checked answer exists and suggest the Explorer.

**The note judges should see** (on Ask, under every answer):
"AI-written at build time by Claude Opus 5.5, checked against the computed data, reviewed by a person. Matched to your question in your browser; no AI service is called and no key is needed."

**Extensible code shape.** `app/src/lib/answer.ts` defines an `AnswerProvider` interface (`answer(question, view) → AsyncIterable<CitedSentence>` plus a `kind` label). Ship one provider, `checkedAnswers` (semantic + keyword). The verifier moves from `ai_build.mjs` into `app/src/lib/verify.ts`, shared by the build and the browser, so a future live provider is checked with the same rules.

## 3. "How the AI works" page (replaces "Method and sources", keeps the sources)
- Diagram: PSI data → arithmetic ranking and gaps → `context.md` → Claude writes briefs, Q&A, related studies → verifier (numbers, PSI IDs, study names) → human sign-off (content hash) → static JSON → browser.
- "Why build-time AI": no keys, no server, no per-visit cost, every sentence checked before publication, reproducible from the repo.
- "AI explains, arithmetic ranks": the score is never set by AI, so it can be checked by hand.
- "Extending to live answers": short description of the bring-your-own-key mode below, marked as not enabled.
- Live stats from `ai_meta.json`.

## 5. Copy
- Header tagline: "SI-powered fire-safety evidence briefings for crewed space missions".
- README: lead with the AI + verifier story and the no-keys choice; keep "Ranking: no AI" as a design principle.
- `DEMO_SCRIPT.md`, `SLIDES.md`: open on the Briefing, then a typed (paraphrased) question, then the "How the AI works" page; Rank math second. Add one slide line: "AI-written, machine-checked, human-reviewed. Zero runtime keys."

## Extension (documented, not built): bring your own key
A second `AnswerProvider`, `liveClaude`, shown only when the visitor opens "Use your own Anthropic key":
- Key kept in `sessionStorage` only, sent only to `api.anthropic.com` via the official TypeScript SDK in browser mode.
- Prompt = cached `context.md` + current view + question; answer streams back; `verify.ts` flags any unsupported sentence; badge "Live AI answer, checked in your browser".
- Used when no checked answer matches, or on demand. A team-hosted proxy (Cloudflare Worker with rate limits and a spend cap) is the alternative if keys should never touch the browser.
